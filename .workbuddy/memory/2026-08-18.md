### 需求
用户要求将景点导览中的"查看详情"按钮改为"AR导览"，点击后进入沉浸式3D实景导览：

- 大气效果：雾效、粒子、装饰山脉和灯笼

## AR 导览 v2.0 - 使用真实景点照片 + 修复缓存问题

### 用户反馈
点击AR导览按钮仍然没有任何反应，且需要使用当地的实际风景照片。

### 根本原因：Service Worker 缓存
`website/sw.js` 使用 **cache-first** 策略缓存所有静态资源（JS/CSS/图片），导致浏览器一直加载旧版本的 AR 代码。旧的 ar-tour.js（v=3）有已知 bug，但 Service Worker 阻止了新版加载。

### 修复内容
1. **Service Worker 升级**（sw.js v1.0.0 → v2.1.0）：
   - JS/CSS 从 cache-first 改为 **network-first**，确保代码最新
   - 升级 CACHE_VERSION 清除所有旧缓存
   - 图片/字体保持 cache-first（不影响功能）
   - HTML 注册加 `?v=2.1` 参数 + updatefound 监听

2. **AR 导览引擎重写**（ar-tour.js v3 → v10，v2.0）：
   - 使用真实景点照片（assets/*.jpg）作为全景球体贴图
   - 新增降级方案：WebGL 不可用时使用 HTML/CSS 全景查看器
   - 鼠标拖拽控制视角（不依赖 Pointer Lock，更可靠）
   - 双击可选启用 Pointer Lock 模式
   - ESC 键退出导览
   - 每步操作都有 console.log 日志

3. **app.js 更新**（v17 → v20）：
   - selectSpot() 和 onMarkerClick() 添加 showToast 提示
   - 点击 AR 按钮即显示"正在打开 AR 导览..."

4. **版本号全部升级**：
   - style.css v=14 → v=20
   - three.min.js v=1 → v=2
   - live2d-integration.js v=23 → v=24
   - data.js v=15 → v=16
   - app.js v=17 → v=20
   - ar-tour.js v=3 → v=10

5. **CSS 新增**：ar-pulse 动画、降级全景容器样式、鼠标 grab/grabbing 样式

## AR 导览权限与 HTTPS 修复

### 用户反馈
1. 手机版点击「开启 AR 导览」没有弹出系统相机/定位权限弹窗。
2. 电脑版首页点击「AR导览」按钮没有反应。

### 根本原因
1. **手机版**：浏览器通过 HTTP（`http://192.168.0.8:3000`）访问时，`navigator.mediaDevices.getUserMedia` 和 Geolocation 处于非安全上下文，浏览器直接拒绝，不会弹出系统权限请求。
2. **电脑版**：`website/css/style.css` 中权限卡片类名是 `ar-cam-permission-card/btn/icon` 等，而 `ar-tour.js` 实际生成的 DOM 使用 `ar-perm-card/btn/icon`，导致权限面板背景/按钮样式全部丢失，界面透明不可见。

### 修复内容
1. **统一并修正 CSS 类名**：
   - `website/css/style.css`：将权限相关类名改为 `ar-perm-*`，与 `mobile.css` 和 `ar-tour.js` 一致。
   - 补充桌面端缺失的 AR UI 样式：`.ar-cam-header`、`.ar-cam-title`、`.ar-cam-fallback`、`.ar-cam-reticle-hint`、`.ar-cam-intro-btn`、`.ar-cam-scanning`、`.ar-cam-result`、`.ar-cam-manual`、`.ar-manual-*` 等。
2. **重写 `ar-tour.js` 权限请求逻辑**：
   - 检测 `window.isSecureContext`，非安全上下文时显示黄色警告提示，引导使用 HTTPS 链接。
   - 支持 `navigator.permissions.query` 预查询权限状态。
   - iOS 13+ 在用户手势内请求 `DeviceOrientationEvent.requestPermission`。
   - 摄像头启动失败时自动降级到模拟模式，并保留手动选择景点入口。
   - 移除电脑版 `index.html` 中遗留的静态空 `arTourContainer`，避免重复 ID。
3. **添加 HTTPS 本地服务**：
   - `server.js` 自动生成自签名证书（`config/ssl/key.pem` + `cert.pem`）。
   - 同时监听 HTTP `:3000` 和 HTTPS `:3443`。
   - 启动日志打印 HTTPS 局域网地址（如 `https://192.168.0.8:3443/mobile/`）。
4. **Cordova APK 权限配置**：
   - `mobile-apk/config.xml` 添加 `cordova-plugin-camera`、`cordova-plugin-geolocation`、`cordova-plugin-device-orientation`。
   - 添加 Android `CAMERA`、`ACCESS_FINE_LOCATION`、`ACCESS_COARSE_LOCATION` 权限。
5. **版本号升级**：
   - 手机版：`mobile.css?v=4`、`ar-tour.js?v=3`、`mobile-app.js?v=7`、`sw.js` v4。
   - 电脑版：`style.css?v=25`、`ar-tour.js?v=15`、`app.js?v=25`、`sw.js` v2.6.0。
6. **新增 `mobile-apk/www/js/config.js`**：为 Cordova file:// 模式提供默认服务器地址和 localStorage 读写函数。

## 桌面端 AR 界面透明无响应修复

### 用户反馈
- 电脑端首页点击「AR导览」后仍然没有反应。

### 根本原因
- `website/css/style.css` 中 `.ar-cam-container` 设置了 `display: none; opacity: 0;`，而 `.ar-cam-container.active` 只覆盖 `opacity: 1`，没有覆盖 `display`。
- `ar-tour.js` 的 `open()` 只设置了 `container.style.display = 'flex'`，但从未添加 `.active` 类，也没有设置 `opacity`，导致 AR 容器是 `display:flex` 但 `opacity:0`，整个界面完全透明，看起来像没打开。

### 修复内容
1. **`website/js/ar-tour.js`**：
   - `open()` 中在 `display = 'flex'` 后添加 `container.classList.add('active')` 和 `container.style.opacity = '1'`。
   - `close()` 中移除 `.active` 并将 `opacity` 重置为 `0`，再隐藏容器。
2. **版本号再次升级**以强制刷新缓存：
   - 电脑版：`style.css?v=27`、`app.js?v=27`、`ar-tour.js?v=27`、`live2d-integration.js?v=27`、`data.js?v=19`、`sw.js?v=2.7`。
   - `website/sw.js` 缓存版本升级到 `v2.7.0`。
   - 手机版：`mobile.css?v=5`、`ar-tour.js?v=5`、`mobile-app.js?v=9`、`config.js?v=5`、`live2d-integration.js?v=5`、`data.js?v=5`。
   - `mobile-apk/www/sw.js` 缓存名升级到 `lingshan-mobile-v6`。
3. 将修复后的 `ar-tour.js` 同步到 `mobile-apk/www/js/ar-tour.js`。

- `website/js/ar-tour.js`、`mobile-apk/www/js/ar-tour.js`：AR 容器显隐逻辑
- `website/css/style.css`：`.ar-cam-container` / `.ar-cam-container.active` 样式
